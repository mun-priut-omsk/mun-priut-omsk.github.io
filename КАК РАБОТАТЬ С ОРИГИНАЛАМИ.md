# Карточки собак и оригинальные фотографии

Дважды щёлкните **Редактор собак.cmd** в этой папке. Откроется окно в обычном браузере. Редактор работает на этом компьютере; сайт в интернете доступен посетителям как прежде.

## Изменить или создать карточку

1. Если вы редактировали карточки прямо на GitHub, нажмите **Обновить с GitHub**. Если изменения ещё не отправлены с компьютера, сначала сделайте **Push origin** в GitHub Desktop.
2. Выберите собаку или нажмите **Новая карточка**.
3. Измените кличку, бирку и статус. Пол и возраст заполняются в отдельных полях: они появятся плашками в карточке на сайте. Если пол не указан или возраст пустой, соответствующая плашка скрыта. Цвет бирки сохраняется в редакторе, но посетителям не показывается. Поле **Описание характера — видно на сайте** показывается посетителям. Старые описания внешности сохранены в свёрнутом разделе **Служебное описание внешности — скрыто на сайте** и используются для поиска по приметам. Для новой карточки добавьте хотя бы одно фото.
4. Нажмите **Сохранить карточку**. Редактор подготовит изменения к отправке.
5. В GitHub Desktop нажмите **Push origin**. После автоматической публикации изменения появятся на сайте.

## Новые фотографии

Нажимайте **Добавить оригиналы** и выбирайте исходные файлы с компьютера. Редактор сначала сохранит точные исходные байты, а для сайта создаст отдельные WebP-копии. Формат и качество оригинала не меняются. Можно выбрать несколько файлов; они обрабатываются по очереди.

Новые фотографии лучше добавлять через этот редактор. Если вы добавили фото вручную на GitHub, его связь с оригиналом автоматически не гарантируется: выберите это фото в локальном редакторе, нажмите **Привязать оригинал** и укажите соответствующий исходный файл.

## Порядок и перенос фотографий

- Кнопка **На обложку** сразу ставит выбранное фото первым. Текущая обложка отмечена.
- Фото можно перетаскивать мышью на нужное место; стрелки тоже сохранены.
- После выбора обложки или смены порядка нажмите **Сохранить карточку**, затем **Push origin**.
- Отметьте фотографии галочками, выберите другую собаку и нажмите **Перенести фото**.
- Для объединения карточек можно перенести все фото и явно отметить **Удалить исходную карточку, если в ней не останется фото**.
- После перестановки нажмите **Сохранить карточку**; перенос сохраняется сразу. Затем **Push origin** в GitHub Desktop.
- Удаление фотографии из карточки не уничтожает её исходник в хранилище.

## Получить архив оригиналов

В нижней части окна выберите:

- **Актуальные карточки на GitHub** — сначала выполняется получение текущего состояния GitHub. Неотправленные локальные изменения в такой экспорт не попадут.
- **Карточки на этом компьютере** — экспортируются локальные сохранённые карточки, даже если вы ещё не нажали Push origin.

Нажмите **Собрать архив оригиналов**. После завершения появится ссылка для скачивания и полный путь уже сохранённого архива. Он лежит рядом с папкой сайта, в **dog_original_exports**. Необязательно скачивать его повторно, если используете файл из этой папки.

В архиве: **Собаки / актуальная кличка / оригинальные фото**, а также **Карточки.csv**, **Карточки.json** и **Экспорт.json**. При совпадении кличек добавляется номер карточки. При совпадении имён разных файлов добавляется порядковый номер, их содержимое сохраняется точно. Большие архивы поддерживают ZIP64.

Экспорт сверяет каждый исходник с его контрольной суммой. Если файл потерян, повреждён или не привязан, законченный архив не выдаётся; отображается причина.

## Где хранятся оригиналы

Отдельная папка **dog_originals** находится рядом с **dog_site**. Внутри **objects** лежат исходные файлы, в **index.json** — связи с фотографиями сайта. Названия файлов внутри хранилища служебные; вручную менять их не нужно. В экспортном архиве возвращаются исходные имена.

Сделайте резервную копию **всей dog_originals**, включая **index.json**, на другой диск. Эта папка не отправляется на GitHub. Копия одного сайта или Download ZIP на GitHub содержит версии для сайта и не заменяет копию оригиналов.

Перемещение фото между карточками и смена кличек не нарушают связи с исходниками. Если вручную переименовать сам файл WebP на GitHub, для нового пути может понадобиться повторная привязка.

Для завершения нажмите **Завершить работу редактора**, затем закройте вкладку.
